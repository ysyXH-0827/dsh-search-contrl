# 采集流程教训库（月报自学习记录）

> 用途：每次月报/日报完成后追加一条复盘，把“踩过的坑”变成下一次的默认动作。
> 写法约束：只写可核对的事实（含数字、命令、文件、时间戳），不写感想。

## 二、失败库（现象 → 根因 → 对策）

| 现象 | 根因 | 对策 |
| --- | --- | --- |
| 日报/月报出现“归档为空”结论 | 用提取通道判空 | 直连抓取 + 打印条目数作为证据 |
| 并行成员 0 落盘 | 任务过宽、无清单、无预算 | 清单制 + 单文件 + 时间预算 |
| 同一 URL 反复抓取 | 无缓存 | 扫描器 12h HTML 缓存、检索 6h 结果缓存 |
| 报告覆盖只到上旬 | 候选清单被 `First N` 截断 | 全月分层抽样（上/中/下旬各取） |
| 链接“死”但实际可用 | 并发触发对方限流 | 429 串行复测 |
| 技能规则写坏语法 | 模板字符串里插入反引号 | 插入前转义/改纯文本 + `npm run check` 前置 |
| 缓存文件误提交 | 脚本写 `.cache/` 未忽略 | `.gitignore` 加 `.cache/`，提交前 `git status` 核对 |

## 五、复盘记录

### 2026-05 月报（47 条：32 主 + 15 中等）

- **目标**：覆盖 2026-05 全月，重大事件为主、中等事件补足密度。
- **结果**：47 条，45 个唯一外链全部可达；覆盖 20 个日期；扫描 2.21 s、校验 435 ms + 328 ms。
- **原因**：中等事件是第二轮补的，第一轮只挑了头条——说明“只挑最大”会系统性丢密度。
- **规律**：月报应固定两轮：第一轮头条（每板块 top 3–5），第二轮中等事件（每板块 3–5），第二轮必须显式标注状态（预告/爆料/计划）。

### 2026-01 月报（39 条）

- **目标**：全月覆盖，首版只有 17 条（上旬）。
- **结果**：补齐中下旬后 39 条，40 链接全 200。
- **原因**：首版用了候选清单前 N 条，天然偏上旬。
- **规律**：抽样必须按旬分层，不能按清单顺序截断。

### 2026-07 / 08 月报（72 / 46 条）

- **结果**：两月共 118 条，128 外链全部 200。
- **原因**：12 个并行 agent 只落 3 个文件；剩余由 Lead 按清单补写。
- **规律**：并行不是目的，**落盘率**才是指标；落盘率低于 50% 时立即切回 Lead 直写。

### 2026-10 周报补采（40 条 / 9 月月报 97 条）

- **结果**：发现并修正“10-13 归档为空”的错误结论，补回苹果发布会、微软 Maia 300、Character.AI 破产等。
- **规律**：任何“为空/不存在”的结论都必须附一条命令级证据（条目数），否则不许写进报告。

## 五、速度实验日志（每次月报至少一次：假设 → 测量 → 采纳/否决）

### 实验 1：链接校验，无界并发 vs 有界并发+重试+缓存（5 月 45 条链接实测）

| 策略 | 耗时 | 成功 | 429 | 结论 |
| --- | --- | --- | --- | --- |
| A 无界 Promise.all（基线） | **475 ms** | 40/45 | **5** | 快 1.26 s，但 11% 假阴性 |
| B 有界并发 6 + 429 退避重试 | 1,731 ms | **45/45** | 0 | 慢 1.26 s，零假阴性 |
| C B + 24h 结果缓存（热） | **5 ms** | 45/45 | 0 | 重复月份近乎免费 |

- **假设**：并发越高越快，因此无界最优。
- **测量**：无界确实快 1.26 s，但产生 5 条 429；这 5 条必须串行复测（每条约 1.5 s），实际代价 **+7.5 s**。
- **结论**：**采纳 B + C**。无界并发只在“愿意人工复测 429”时使用；默认走有界 + 重试 + 缓存，净收益约 **+6.2 s**。
- **工具**：`scripts/verify-links.mjs`（`--concurrency`、`--retries`、`--cache-hours`）。

### 实验 2：检索并发（6 条 Bing 查询）

| 策略 | 耗时 | 结论 |
| --- | --- | --- |
| 串行 | 1,412 ms | 基线 |
| 并发 4 | 604 ms | 采纳 |
| 并发 4 + 6h 缓存 | **5 ms** | 采纳 |

- **结论**：并发 4 是“速度/限流”的平衡点；再高需要验证 429 率（待下次实验）。

### 2026-10-23 设置页 GUI（1.5.0）

- **结果**：新增渲染进程配置页，支持自定义搜索源、自定义主题（不限科技）、博主主页链接定向检索；所有写入都可回退。
- **可回退的实现**：不是「保存前备份」，而是 **保存时先把被替换的旧版本写进 `history/<ISO>.json`，再写 `settings.json`**；重置与回退走同一条路径 —— 于是「回退」这个动作本身也会被快照，点错一次还能再退回来。
- **不写 profile patch 的原因**：profile 的 `cordis.patch.yml` 是 Host 合成的配置层，插件运行期改写它等于让 Host 和插件同时改同一份文件，冲突无解；自带 `settings.json` + 历史目录才是可回退的边界。数据目录 `~/.dsh/plugin-data/<id>/`，可用 `TECH_DAILY_REPORT_DATA_DIR` 覆盖。
- **规律**：**凡是要「可回退」的功能，回退动作本身必须被记录**；只备份写前状态的回退是一次性的。

### 无浏览器怎么测渲染进程 bundle

- **问题**：设置页代码在浏览器里跑，profile 的 `node_modules` 没有 `react`，无法直接 SSR 或浅渲染；真跑起来只能靠人肉点。
- **做法**：`scripts/test-client.mjs` 用 stub 的 `react`（`useState`/`useCallback`/`useEffect`/`createElement`）+ stub 的 `react/jsx-runtime` 造一个假 `require`，把 `lib/client.js` 源码用 `new Function('window', source)` 塞进假 `window.__ModuleLoader__`，然后断言 **模块 id、`exports.apply`/`exports.inject`、slot 名与 key、summary 文案、卡片树里的各 tab 与按钮文案、平台解析映射**。
- **取舍**：这不是渲染测试，不验证像素与交互；验证的是「注册契约 + 结构 + 文案」，正好是插件装上后最容易炸、也最不容易在浏览器里定位的部分。
- **规律**：**渲染进程代码也要有可自动化的契约测试**，否则每次改动都得重启 Host 人肉点一遍，回归成本高到不会去做。

### 「设置里看不见」：plugins.row.config 不是设置侧边栏

- **症状**：客户端 bundle 注册成功、插件行配置页也在，但用户在「设置」左侧导航里看不到任何东西。
- **根因**：DSH 里这是两个不同的 slot。`plugins.row.config` 只挂到 **插件行**（设置 → 插件 → 该插件）的配置视图；要让条目出现在**设置窗口左侧的一级导航**，必须注册 `settings.section`。
- **做法**：`ctx.slots.inject('settings.section', () => ctx.slots.register({ name: 'settings.section', id: '<唯一 id>', order: <数值>, label: '搜索控制' }, Component))`；同时 `package.json` 的 `dsh.client.inject` 要声明 `@deepseek-ai/dsh-client-ui-settings` 与 `@deepseek-ai/dsh-client-ui-slots`，否则渲染进程拿不到设置窗口提供的运行环境。`order` 决定排序：已装插件的分区占 100–151，本插件取 152。
- **保留两个入口**：同一张卡片同时挂 `settings.section`（一级分区，`page: true`）与 `plugins.row.config`（行配置页，summary 折叠形态），用户从哪进都能改。
- **规律**：**"注册成功"不等于"出现在用户找的位置"**——交付前先问：用户会去哪个界面找它，那个界面对应哪个 slot？
